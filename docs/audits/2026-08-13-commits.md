# Commit Audit: `dad3d78^..c027311`

**Verdict:** The range adds useful status, Action, completion, lifecycle, and retention behavior, but it should not be treated as concurrency-safe or filesystem-hardened until AP-001 through AP-003 are fixed. The baseline test, race, vet, and fuzz runs passed; those checks did not exercise the confirmed lock, parent-symlink, publication-correlation, or Action contract gaps.

## Scope and method

This audit covers exactly the ten commits in `dad3d78^..c027311`, ending at `c02731163894d1f11eb9ffcb0eaed709d98e255e`. It does not assess earlier behavior except where needed to establish causality.

The review combined:

- commit-by-commit patch inspection and comparison with the final tree;
- source tracing across record lifecycle, purge retention, status publication, completion generation, doctor output, and the composite Action;
- race, symlink, process, retention, and mixed-generation threat modeling;
- existing test and fuzz-oracle inspection;
- independent challenge of proposed findings and explicit down-ranking where the evidence did not support the stronger claim.

### Review coverage and limitations

Six reviewer lanes were used:

The Codex failure means this report contains no Codex verdict. The adversarial refuter did not reach a conclusive verdict. Findings were therefore accepted or rejected from reproducible source behavior and bounded threat-model evidence, not from reviewer consensus. Claims about active malicious path replacement remain qualified rather than presented as proven exploitability.

## Per-commit assessment

### 1. `dad3d78` — `fix(status): populate verification fields from emitted evidence`

**Files:** `internal/status/status.go`, `internal/status/status_test.go`

The commit correctly moves status and bundle extraction to the top-level evidence schema and sources the verification timestamp from the attestation. Its tests cover valid, missing, and malformed documents. However, evidence and attestation are read separately, and the attestation bundle ID is ignored. A reader can transiently combine evidence from one publication with the timestamp from another (AP-008).

### 2. `999fc1c` — `feat(action): write verification report to the job step summary`

**File:** `action.yml`

The `if: always()` summary step improves policy-failure visibility and leaves the verification step's explicit `exit "$verify_code"` intact. The final report test and `cat` both follow a symlink, creating a local runner-file disclosure path (AP-007). The Action has no integration or contract coverage for summary behavior or exit preservation (AP-013).

### 3. `4e8d22e` — `feat(completion): add bash, zsh, and fish shell completions`

**Files:** `internal/app/app.go`, `internal/app/app_test.go`, `internal/completion/completion.go`, `internal/completion/completion_test.go`

The generator and unsupported-shell behavior are useful and tested. The hand-maintained command table also omitted the subsequently added `purge --runs` option, contradicting the single-source-of-truth comment (AP-012).

### 4. `34a76ea` — `test(fuzz): add fuzz targets for untrusted parsers`

**Files:** `internal/scan/fuzz_test.go`, `internal/session/fuzz_test.go`, `internal/testresult/fuzz_test.go`

The fuzz targets add valid panic-resistance coverage and exercised substantial input counts in the fresh baseline. Most targets stop at “must not panic.” In particular, `FuzzScanPatch` promises visible incomplete-scan evidence but never asserts it (AP-014). This is a missing oracle, not a reason to remove no-panic fuzzing.

### 5. `969ee7c` — `feat(record): track run lifecycle state and guard parallel records`

**Files:** `internal/config/config.go`, `internal/record/raise_unix.go`, `internal/record/raise_windows.go`, `internal/record/record.go`, `internal/record/record_test.go`

Lifecycle state files and signal-aware abandonment are valuable. The lock implementation is not an exclusive lock: it reads a PID, checks process liveness, and then writes the path. Targeted SIGINT/SIGTERM reaches the wrapper's handler but is not explicitly forwarded to the child (AP-006).

## Consolidated findings

### AP-001 — P1 — Record lock is not mutually exclusive

- **Location:** `internal/record/record.go:257-270`
- **Causal commit:** `969ee7c`
- **Evidence:** `acquireLock` performs `ReadFile`/PID liveness checks before `WriteFile`; acquisition is not atomic. The release closure unconditionally removes the shared path.
- **Minimal reproduction:** Start two helper processes behind a barrier, let both call `acquireLock` after observing no live PID, and release the first after the second writes. Both can report acquisition; the first release can delete the second process's path.
- **Impact:** Two records can write overlapping repository windows, violating the exclusive-record invariant. Release can also remove the visible ownership marker for another process.

### AP-002 — P1 — Lock creation follows a final symlink

- **Location:** `internal/record/record.go:257-270`
- **Causal commit:** `969ee7c`
- **Evidence:** `os.WriteFile(lockPath, ..., 0o600)` follows a final symlink and truncates its target.
- **Minimal reproduction:** Replace `.agentproof/.record.lock` with a symlink to a writable sentinel, call record, and inspect the sentinel after acquisition.
- **Impact:** A local actor who controls the repository metadata path can truncate and overwrite a writable file reachable from the runner account.

### AP-003 — P1 — Purge trusts a symlinked runs parent

- **Location:** `internal/purge/purge.go:71-129`
- **Causal commit:** `3c63394`
- **Evidence:** `Runs` joins `.agentproof/runs` and immediately calls `os.ReadDir`; it does not establish that the parent is a contained, real directory before selecting and removing children.
- **Minimal reproduction:** Point `.agentproof/runs` at an external directory containing an old run-shaped directory with `state.json` marked abandoned, then run confirmed `purge --runs`.
- **Impact:** Eligible directories outside the intended `.agentproof/runs` tree can be selected and deleted.
- **Boundary:** Direct child symlinks are skipped. This finding does not claim that every child symlink is traversed.

### AP-004 — P2 — Run-state reads are unbounded and follow symlinks

- **Location:** `internal/purge/purge.go:111-129`
- **Causal commit:** `3c63394`
- **Evidence:** `deadRun` calls `os.ReadFile(filepath.Join(dir, "state.json"))` without a size bound or final-symlink rejection.
- **Minimal reproduction:** Use a run directory whose `state.json` is a symlink to a large readable local file, then preview `purge --runs`.
- **Impact:** Purge can perform unintended local reads and allocate based on attacker-controlled file size, creating local disclosure and parser/resource-exhaustion risk.

### AP-005 — P2 — PID-only lock liveness is not ownership

- **Location:** `internal/record/record.go:240-270`
- **Causal commit:** `969ee7c`
- **Evidence:** The lock contains only a PID and treats any live process with that PID as the owner.
- **Minimal reproduction:** Place the PID of an unrelated live process in `.record.lock`; acquisition is rejected indefinitely. PID reuse after an owner exits has the same effect.
- **Impact:** False liveness blocks recording and makes stale-owner recovery unreliable.
- **Disposition:** Subsumed by the OS-backed lock protocol in the remediation plan.

### AP-006 — P2 — Targeted wrapper signals are not explicitly forwarded

- **Location:** `internal/record/record.go:70-82,87+`
- **Causal commit:** `969ee7c`
- **Evidence:** The handler marks the run abandoned and re-raises the signal in the wrapper; it does not explicitly signal the child before wrapper termination.
- **Minimal reproduction:** Target SIGTERM at the wrapper PID only while a child ignores parent death and records its continued execution.
- **Impact:** A child can outlive a specifically signaled wrapper and continue mutating the repository after the captured window is marked abandoned.
- **Boundary:** Ordinary interactive Ctrl-C generally targets the foreground process group and often reaches both processes. This report does not claim that normal terminal interruption always strands the child.

### AP-007 — P2 — Step Summary follows a report symlink

- **Location:** `action.yml:89-93`
- **Causal commit:** `999fc1c`
- **Evidence:** Both `[ -f .agentproof/report.md ]` and `cat .agentproof/report.md` follow a final symlink under `if: always()`.
- **Minimal reproduction:** Make the report path a symlink to a readable runner file and execute the summary step.
- **Impact:** The target file's contents can be appended to the public or retained job Step Summary.
- **Boundary:** The default Action declares no secrets and does not receive a write token. Arbitrary runner-file disclosure is supported; credential leakage is not proven.

### AP-008 — P2 — Status can mix publication generations

- **Location:** `internal/status/status.go:57-83`
- **Causal commit:** `dad3d78`
- **Evidence:** Evidence and attestation are atomically written individually but sequentially. Status reads them independently and does not compare their bundle IDs.
- **Minimal reproduction:** Pause publication after a new `evidence.json` replaces the old file but before the matching `attestation.json` is written, then call status.
- **Impact:** Status can transiently report a new result and bundle with an old verification timestamp.

### AP-009 — P2 — One active record preserves every recording directory

- **Location:** `internal/purge/purge.go:111-129`
- **Causal commit:** `3c63394`
- **Evidence:** `deadRun` treats any `recording` state as live whenever global `record.LiveRecord(root)` is true; it does not correlate the lock with a run ID.
- **Minimal reproduction:** Leave an old `recording` directory, start a new live record, and preview run purge after the old directory passes the age threshold.
- **Impact:** Retention silently preserves stale recording directories while unrelated work is active. This is safe from deletion but semantically incorrect and can cause unbounded retention.
- **Boundary:** Doctor's subtract-one count remains logically correct for the current global model.

### AP-010 — P2 — Directly sourced zsh completion is not registered

- **Location:** `internal/completion/completion.go:59+`
- **Causal commit:** `4e8d22e`
- **Evidence:** `#compdef` is interpreted during completion-function discovery, not as a command when the generated text is directly sourced. The script does not call `compdef _agentproof agentproof`.
- **Minimal reproduction:** Run `autoload -Uz compinit && compinit`, source the documented process substitution, and query completion registration for `agentproof`.
- **Impact:** The documented zsh setup can load the function without registering it for the command.

### AP-011 — P3 — Doctor recommends an invalid purge command

- **Location:** `internal/doctor/doctor.go:58+`
- **Causal commit:** `f3a578a`
- **Evidence:** The warning recommends `agentproof purge`, while `purgeCommand` rejects invocations without `--raw` or `--runs`.
- **Minimal reproduction:** Trigger an abandoned-run warning and execute the printed command.
- **Impact:** The operator receives a usage error instead of a retention preview.

### AP-012 — P3 — Completion omits `purge --runs`

- **Location:** `internal/completion/completion.go:30`
- **Causal commits:** `4e8d22e` introduced the manual table; `3c63394` added the omitted option.
- **Evidence:** The purge completion entry lists `--raw`, `--older-than`, and `--confirm`, but not `--runs`. The comment calling the table a shared source of truth does not match the architecture.
- **Minimal reproduction:** Generate any supported shell completion and inspect suggestions after `agentproof purge`.
- **Impact:** Users are not offered the run-retention selector, and future CLI drift remains possible.

### AP-013 — P2 — Action Step Summary has no contract coverage

- **Location:** `action.yml` Step Summary behavior
- **Causal commit:** `999fc1c`
- **Evidence:** The commit changes only `action.yml`; no test exercises success, policy failure, missing or unreadable reports, symlink rejection, or verification exit-code preservation.
- **Minimal reproduction:** Search the test suite for Action execution or Step Summary assertions; none cover this behavior.
- **Impact:** Regressions can hide policy-failure reports, leak unintended report targets, or alter the Action's final outcome without detection.

### AP-014 — P3 — Fuzz targets lack promised behavioral oracles

- **Location:** `internal/scan/fuzz_test.go`, `internal/session/fuzz_test.go`, `internal/testresult/fuzz_test.go`
- **Causal commit:** `34a76ea`
- **Evidence:** The fuzz callbacks mostly discard results. `FuzzScanPatch` explicitly promises incomplete-scan evidence for oversized lines but only calls `Run`.
- **Minimal reproduction:** Mutate the scanner so an oversized line returns no `AP-SCAN-001`; the current fuzz target still passes if no panic occurs.
- **Impact:** Semantically wrong parser and scanner behavior can survive high fuzz execution counts.
- **Boundary:** Panic resistance is valid intended coverage and must remain alongside stronger properties.

## Accepted, refuted, and down-ranked claims

### Accepted

- The record lock violates mutual exclusion and ownership-safe release.
- The lock write follows a final symlink.
- A symlinked `.agentproof/runs` parent can relocate purge outside the intended tree.
- `deadRun` performs an unbounded, symlink-following read.
- PID-only liveness, publication mismatch, global retention, zsh registration, doctor guidance, completion drift, Action contracts, and fuzz oracles are confirmed gaps.

### Refuted or constrained

- **“Every purge child symlink is traversed.”** Refuted. `entry.Type()&os.ModeSymlink != 0` skips direct run-directory symlinks.
- **“A child swapped to a final symlink makes `RemoveAll` recurse into its target.”** Refuted for the observed implementation. `RemoveAll` removes the link rather than traversing the target.
- **“Concurrent destructive replacement is proven exploitable.”** Not established. Active replacement of validated path components needs a stronger threat model and descriptor-relative platform primitives; it remains a residual concern.
- **“The Action leaks credentials.”** Down-ranked. Local runner-file disclosure is demonstrated; credentials are not present by default and credential leakage was not proven.
- **“Ctrl-C always leaves the child alive.”** Refuted as stated. Normal foreground-terminal Ctrl-C usually reaches the process group. The confirmed case is a signal targeted only at the wrapper.
- **“No-panic fuzzing is worthless.”** Refuted. It is valid coverage, but it does not satisfy the behavioral promises in the comments.

## Final verdict

The ten-commit range is functionally valuable and passes its current baseline, but the P1 findings invalidate the advertised exclusivity and local-tree retention boundaries. Remediation should first replace the lock protocol, then harden purge containment, and only then address signal, status, Action, CLI, and fuzz-contract gaps. The companion plan at `docs/superpowers/plans/2026-08-14-audit-remediation.md` orders that work under strict TDD and preserves the refuted-claim boundaries above.
